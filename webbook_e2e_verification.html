1. 验证过程中暴露并修复的 Bug

Postgres int32 溢出：首次真实触发时后台研究在 1.5s 内失败，报错 invalid input for query argument $10: 1784470185451 (value out of int32 range)。

根因（双因素）：

  • P3 代码 trigger_service.py 给节点计时传入 started_at = time.monotonic()， 而 record_node_success 内部用 time.time() 计算 finished_at 与 duration_ms = int((finished_at - started_at) * 1000)。
  • time.monotonic() 与 time.time() 是不同 epoch 的时钟，相减得到约 1.78e12 ms 的伪耗时， 远超 INTEGER（int32，上限 2,147,483,647）。
  • 该 Bug 仅 trigger 路径命中（/chat 路径用的是 time.time()，单元测试不连 PG 未暴露）。

修复（双保险）：

  • 改为每个节点循环内 node_started_at = time.time()，与 /chat 口径一致。
  • 新增迁移 20260720_0009_widen_duration_ms_bigint.py，将三张 trace 表 duration_ms 由 INTEGER → BIGINT（downgrade 可逆）。
